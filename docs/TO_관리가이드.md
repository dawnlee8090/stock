# T/O 문제점 관리 가이드

T/O 문제점 대장을 꾸준히 쌓아서 **재발을 막고, 다음 차종에서 같은 문제를 미리 피하기** 위한 운영 규칙입니다.

## 1. 언제 무엇을 하나

| 시점 | 할 일 | 명령 |
|---|---|---|
| T/O 결과 메일·보고서를 받으면 | 불량 1가지 = 1건으로 등록 (사진 포함) | Claude `/to-update` 또는 `to add` |
| 원인이 나오면 | 원인 구분 + 원인, 상태 `원인분석` / `대책수립` | `to set <T> --cause-cat .. --cause ..` |
| 대책이 정해지면 | 대책 구분 + 대책 + 담당 + **대책 목표일** | `to set <T> --action-cat .. --cm .. --owner .. --due ..` |
| 대책을 적용하면 | 상태 `대책적용` + **확인 목표일**(다음 T/O) | `to set <T> --status 대책적용 --verify-due ..` |
| 다음 T/O 결과가 나오면 | 효과 확인 → `유효`면 `종결`, `부분`/`무효`면 새 대책 | `to set <T> --result .. --effective 유효 --status 종결` |
| 대책이 막히면 | 과거 이력·유사 사례 기반 개선안 | Claude `/to-advice <T>` |
| 매주 (회의 전) | 신규·지연·재발·종결 정리, 다음 주 할 일 | Claude `/to-weekly` → `to export` |
| 매일 아침 (자동) | 지연·임박 알림, 새 관련 메일 연결 | 작업 스케줄러 (`to check --notify`) |

## 2. 입력 규칙 (통계와 유사 사례 검색이 잘 되려면)

- **불량 1가지 = 1건.** 한 부품에 싱크와 웰드가 같이 나오면 2건으로 나눕니다.
- **품번은 전체 형식**(86511-BN200). LH/RH 한 쌍은 `86525/26-BNGA0` 처럼 써도 됩니다.
- **현상에는 수치**를 넣습니다: "싱크" 대신 "보스 뒷면 싱크 0.15mm (A면, 한도 0.05)".
- **불량 유형**은 표준 이름이 자동으로 붙습니다 (싱크, 웰드라인, 변형, 미성형, 버, 단차·갭, 감싸기·접착 등 21종). 다르게 붙으면 `--defect` 로 고칩니다.
- **원인 구분 / 대책 구분**은 꼭 고릅니다. 불량 통계 시트에서 "금형 원인이 몇 %인지", "조건 변경으로 끝난 비율"이 보입니다.
  - 원인 구분: 성형조건 / 금형 / 제품설계 / 재질 / 설비 / 검사구 / 조립·공정 / 미확인
  - 대책 구분: 조건변경 / 금형수정 / 설계변경(E.O) / 재질변경 / 설비·지그 / 검사기준 / 작업표준
- **효과는 반드시 남깁니다** (유효 / 부분 / 무효). 다음에 같은 문제가 생기면 "효과 확인된 대책"이 맨 위에 나옵니다.
  효과가 없었던 대책도 지우지 말고 `무효`로 남겨야 같은 실수를 반복하지 않습니다.
- **설계 변경이 필요한 대책**은 E.O 항목과 연결합니다: `to set <T> --eo <E번호>`
- **사진**: 불량 부위 사진·단면·측정 결과 캡처를 붙입니다 (`to img <T> --collect` 또는 캡처 후 `--paste`).

## 3. 종결 기준

- 다음 T/O(또는 양산 초기 로트)에서 **규격 이내 확인** + 효과 `유효` → `종결`
- 고객사·품질 승인 조건이 있으면 승인 메일을 연결(`to link <T> <메일번호>`)한 뒤 종결
- 일정상 다음 차수로 넘기는 건은 `보류`가 아니라 **진행 상태 유지 + 확인 목표일 변경**

## 4. 재발했을 때

등록하면 `↻재발`과 함께 이전 원인·대책·효과가 나옵니다. 아래를 확인합니다.
1. 이전 대책이 **실제로 적용됐는지** (금형 수정 이력, 조건표 반영 여부, 현지 성형처 조건 이관 여부)
2. **원인이 같은지** (조건 산포, 금형 마모, 재질 로트, 현지 설비 차이)
3. 이전 대책이 `부분`/`무효`였다면 **다음 단계 대책**으로 (조건 → 금형 → 설계 → 재질)

## 5. 과거 이력 쌓기 (처음 한 번)

대장이 비어 있으면 유사 사례 조언이 약합니다. 지난 T/O 메일부터 차근차근 넣어 두세요.
```
/to-update 2025년 BC4t
/to-update 2026년 상반기
```
